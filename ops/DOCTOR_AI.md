# «Доктор ИИ» — сторож здоровья (Royal Home)

Лёгкий сторож, который следит, чтобы сайт и CRM не падали, и сам поднимает их
обратно, если что-то упало. Скрипт: [`health-watchdog.sh`](health-watchdog.sh).

## Что делает
- Раз в несколько минут проверяет: сайт отвечает `HTTP 200`? CRM отвечает? (через `curl`).
- Если сервис не отвечает — делает **одну** попытку `docker compose restart` и проверяет снова.
- Шлёт тебе сообщение в Telegram **только когда состояние изменилось**: «🔴 упал» или «🟢 восстановился». Никаких отчётов «просто так».

## Почему это бесплатно
Проверка — это обычный `curl` + `docker`, который крутится на **твоём же VPS**
(за него ты и так платишь). **ИИ при проверке не вызывается**, токены не тратятся.
Деньги ушли бы, только если бы мы дёргали ИИ на каждую проверку — мы так не делаем.
Поэтому проверять можно часто (раз в 3 минуты), чтобы падение ловилось за минуты.

## Установка (один раз, на сервере под root)
```bash
# 1. Скопировать скрипт
cp ops/health-watchdog.sh /opt/health-watchdog.sh
chmod +x /opt/health-watchdog.sh

# 2. (Рекомендуется) вписать Telegram-данные, чтобы приходили уведомления
cat > /opt/watchdog.env <<'EOF'
TELEGRAM_BOT_TOKEN=ВАШ_ТОКЕН_ОТ_BotFather
TELEGRAM_CHAT_ID=ВАШ_CHAT_ID
EOF

# 3. Проверить вручную
/opt/health-watchdog.sh ; echo "exit=$?"

# 4. Поставить в cron (каждые 3 минуты)
crontab -e
# добавить строку:
*/3 * * * * /opt/health-watchdog.sh >> /var/log/royalhome-watchdog.log 2>&1
```

### Как получить Telegram-данные
1. Написать [@BotFather](https://t.me/BotFather) → `/newbot` → получить **токен**.
2. Написать своему новому боту любое сообщение, затем открыть
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найти там `chat.id` —
   это твой **CHAT_ID**. (Или спросить у [@userinfobot](https://t.me/userinfobot).)

## Настройки (необязательно, в `/opt/watchdog.env`)
| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SITE_URL` | `http://127.0.0.1/` | Куда стучаться, чтобы проверить сайт |
| `CRM_URL` / `CRM_HOST_HEADER` | `http://127.0.0.1/` + `crm.royalhome.tj` | Проверка CRM через Caddy по Host-заголовку |
| `SITE_DIR` / `CRM_DIR` | `/opt/royalhome-site` / `/opt/royalhome-crm` | Каталоги с `docker-compose.prod.yml` |
| `HTTP_TIMEOUT` | `10` | Таймаут запроса, сек |

## Что это НЕ делает (осознанно)
Не переписывает код при поломке. Автоправка кода в проде рискованна (может
сломать больше). Сторож лечит то, что реально лечится перезапуском (зависший
процесс, упавший контейнер, разовый сбой), а про остальное — сообщает тебе.

## Возможное развитие (по желанию, позже)
Если захочешь «ИИ-диагностику»: сторож может при поломке собрать последние
строки логов (`docker compose logs --tail=200`) и один раз отправить их в ИИ,
чтобы прислать тебе готовый разбор причины и предлагаемый фикс — но **применять**
его ты будешь сам кнопкой. Это уже тратит немного токенов (только в момент
реальной аварии, не на каждую проверку). Скажи — добавлю.
